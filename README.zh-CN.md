## 👁️ 缺少的变量，是观察

> *“我们不直接画水，而是画水经过时留下的变化——翻滚的白泡沫、飞溅的水花，以及物体身后散开的气泡尾迹。”*

这个项目不是从流体求解器开始的，而是从一种怎么调都不对劲的感觉开始：下落轨迹明明已经合理，海水也在动，可画面就是没有真正“活起来”。

转折发生在我和女儿一起慢慢看一本儿童绘本时。那些粉笔般的泡沫、断开的蜡笔圈和串珠似的尾迹，并不只是风格装饰，而是插画家从长期观察中提炼出的画面线索。它们只画出最关键的变化，看画的人会用自己对水的身体记忆，把没有画出来的运动补完。

**Wax and Water 不是要把水完整地“算出来”，而是要抓住那些让人一眼觉得“这就是水”的线索。** 它用了几条从观察出发、又有简单物理依据的启发式规则：气泡会上浮，尾迹会记住物体走过的路，被带入水中的空气会逐渐释放，而颜料移动时，纸纹仍然留在原处。每条规则都不是完整的流体模型，但放在一起，已经足以让蜡笔画出的记号像水一样动起来。

## ⚡ 这项实验在探索什么

网页里的水，可以用 3D 模拟、着色器，也可以直接播放预先做好的动画。**Wax and Water** 选择了一条更轻的 2D 路：不去完整模拟水，而是把从现实和绘本里观察到的规律，写成几条能够实时运行的启发式规则。

1. **所有水花都在互动时现算**：水面泡沫、湍流尾迹和一串串的气泡，都是在你操作时实时生成的，不是预先做好的动画循环。仓库里的 GIF 预览，只是这套实时系统的录屏。
2. **落得多快，决定溅得多大**：入水速度会同时改变带入水中的空气量、水面泡沫的宽度、水下气团的深度和飞溅强度。入水以后，这笔有限的“空气预算”会按指数规律越放越少。
3. **尾迹会记住物体走过的路**：气泡在物体经过的位置产生，一开始带着一部分物体的速度，之后再慢慢向上浮。所以我们看到的尾迹，其实是“物体走过的路 + 每颗气泡离开后经过的时间”。
4. **泡泡挤在一起，就会变成粉笔团**：气泡密集时，画成厚实的白色粉笔块；散开以后，则逐渐变成松散的手绘蜡笔圈。
5. **气泡从真正的背水侧脱落**：产生气泡的位置不是预先写死的。程序会读取物体轮廓，再结合它当时的运动方向，决定气泡更容易从哪一边离开。
6. **纸纹不跟着气泡跑**：颜料和气泡会移动，但纸张的纤维纹理一直留在屏幕原处，所以画面不会像贴纸一样整块滑过去。

这是一个创意编程实验，不是计算流体力学求解器。这里的公式不负责预测真实水流，只负责让动作看得懂、让插画的节奏成立。

## 🤿 三种物体，同一套程序

三个物体共用同一套模拟和绘制逻辑，但各自有一组调好的参数，比如下沉速度、浮力、带入水中的空气量和泡沫大小。所以，它们的差别不只来自外形。

* 🤿 **潜水面镜（宽扁 · 浮力大）**：迎水面积大，入水时会推开一大片泡沫，身后拖着串珠般的气泡，呼吸管还会再咕嘟几下。
* 📷 **水下相机（方正 · 较沉）**：下沉更快，刚入水的气团更紧，气泡容易从方形边缘和外露的尖角处脱落。
* ✏️ **蜡笔（细长 · 阻力小）**：切入水面时几乎不溅起水花，只在身后留下一条细长的尾迹。

## 💡 核心启发式模型

这里没有求解 Navier–Stokes 方程，而是用一组够轻、够快，看起来也足够成立的启发式规则，去唤起儿童绘本里那种温暖、可触摸的水下感觉：

| 想法 | 怎么做 | 为什么这样做 |
| :--- | :--- | :--- |
| **一次入水，带出一整套反应** | 入水速度设定整体冲击强度；尾迹气泡的释放率遵循 $r(t) = r_0 e^{-t/\tau}$ | 泡沫、水下气团、飞溅和后续尾泡都来自同一次入水，不需要在几段预制动画之间生硬切换。 |
| **气泡跟着轮廓找出口** | $w = \max(0, \mathbf{n} \cdot (-\hat{\mathbf{v}}))^{1.5} + 0.35(1-|\mathbf{n}\cdot\hat{\mathbf{v}}|)$ | 比较轮廓法线 $\mathbf{n}$ 和运动方向 $\hat{\mathbf{v}}$，让气泡更容易从背水侧和外露尖角脱落。 |
| **泡泡越挤，画得越实** | 检查附近有多少颗气泡，以及它们的尺寸是否重叠 | 密集的地方逐渐变成实心粉笔团；散开的气泡逐渐变成空心蜡笔圈。 |
| **纸不动，颜料在动** | 离屏图层配合 `destination-in` 合成 | 把纸张纤维固定在屏幕坐标上，让颜料和气泡从它上面经过。 |
| **物理负责连贯，艺术负责收稳** | 重力、浮力、线性/平方阻力，再加一次定时收稳 | 让下潜过程看起来连贯，最后又能柔和地悬浮下来；它不假装自己是严格的物理平衡。 |
| **调好以后可以直接分享** | `?obj=...&terminal=...` 等 URL 参数 | 把选定的物体、语言、时刻和关键参数放进链接，别人打开就能看到同样的状态。 |

## 🔬 技术实现细节

  <br>
  <em>空中悬停 → 入水泡沫 → 串珠尾迹 → 柔和地悬浮下来。</em>
</p>

### 1. 气泡从哪里脱落：轮廓法线加权

如果气泡永远从几个写死的位置冒出来，物体一旋转或倾斜就会穿帮。所以，在浏览器允许读取像素时，程序会从图像的 Alpha 通道里采样 96 个边界点，并算出它们的外法线。通过 `file://` 直接打开页面时，则使用项目里预先算好的轮廓。每个边缘点产生气泡的权重是：

$$w = \max(0, \mathbf{n} \cdot (-\hat{\mathbf{v}}))^{1.5} + 0.35(1 - |\mathbf{n} \cdot \hat{\mathbf{v}}|)$$

其中 $\hat{\mathbf{v}} = \mathbf{v} / \|\mathbf{v}\|$ 是单位速度向量。简单来说，物体一转向或摇晃，气泡脱落的位置也会跟着移到当时的背水侧。

### 2. 泡泡挤不挤，决定它画成什么

在绘本里，挤在一起的泡沫看起来像柔软、厚实的粉笔团；散开上浮的泡泡，则更像一个个松散的手绘圆圈。每颗气泡会寻找附近的同伴：先用 40px 范围粗筛，再根据双方的大小判断它们是不是真的靠得很近。附近有 3 颗以上时，它会慢慢变成实心粉笔点；附近变空时，又会慢慢变回空心蜡笔圈。这个变化被刻意放慢，避免在临界点附近忽实忽空地闪烁。面板里的「空心泡多少」可以在两种判法之间连续调节：0 时前后景邻居都算数、新泡从实心开始；1 时只数同一深度的邻居、新泡从空心开始。

### 3. 颜料在动，纸纹不动

数字蜡笔很容易出现一个破绽：噪点跟着气泡一起移动，看起来就像一张贴纸在屏幕上滑。在这个项目里，水花、气泡和尾迹会先以实心形状画到离屏 Canvas 图层上，再通过 `destination-in` 套上固定不动的纸纹。颜料在走，纸纹在留。

### 4. 手绘感来自“有规律的不完美”

手绘感不等于每一帧都重新乱抖。这里的涟漪是不闭合的断弧，气泡轮廓会有轻微抖动和有意留下的断口，笔触也会忽粗忽细。但这些不完美要么来自固定的随机种子，要么经过时间平滑，所以它们会一直保持手绘感，却不会在动起来时乱闪。

### 怎么玩

* **点击物体**：触发自由落体入水。
* **拖拽物体**：改变空中的释放高度，对比不同入水速度。
* **Space（空格）**：回到初始悬浮位置。
* **P**：暂停或继续模拟。
* **C**：呼出或收起九组实时调参面板。
* **贴纸切换**：在潜水面镜 🤿、水下相机 📷 和蜡笔 ✏️ 之间切换。

### 可以复现的分享链接

链接里可以直接带上物体、语言、时刻和单项参数。点击“复制链接”时，页面会保留一组最常用的设置：

* `?obj=crayon&terminal=480&spreadRate=160` — 高速蜡笔入水
* `?obj=camera&lang=en` — 英文界面的相机参数组
* `?obj=mask&t=1.0` — 跳转到接触水面后 1 秒

## 🧭 它是怎样长出来的

1. **先把“笔触的形状”和“纸张的颗粒”拆开。** 早期试过三种实时画法。最重要的收获不是找到一个更漂亮的笔刷，而是想清楚了一件事：笔尖只负责画出形状，颗粒感应该来自固定不动的纸张。
2. **先观察，再模拟。** 逐页看 Jacqueline Davies 与 Sonia Sánchez 的绘本《Bubbles... Up!》时，我们整理出了几种最关键的画法：密集的粉笔泡沫、空心泡泡圈、串珠般的尾迹，以及那些能让静止画面看起来正在流动的环境笔触。
3. **推翻一个没有根据的规则。** 第一版的气泡永远从镜片下方几个固定点冒出来。但画面一看就不对：气泡不应该无视物体的方向和轮廓。现在的轮廓法线加权，就是从这个破绽里长出来的。
4. **再把单个潜水镜扩展成一套可复用的规则。** 最初只有潜水镜原型，后来才加入不同轮廓和参数的相机与蜡笔，再补上中英双语、手机与桌面布局，以及可以复现当前设置的分享链接。

整个过程是被一轮轮观察和判断推着向前的。一个看起来不对的假设、一个其实没有生效的参数，或是一组并排对照图，都是继续往下做的证据，而不是需要藏起来的失败。

## 📖 创作背景与灵感

* **《海底总动员》的童年记忆**：潜水镜缓缓沉入蓝色深处的意象，来自童年对一个普通人类物件坠入巨大海洋空间的记忆。这个实验没有追求电影式 3D 质感，而是转向纸板、蜡笔与绘本物理。
* **《Bubbles... Up!》绘本观察**：与女儿一起读这本绘本时，我们特意停下来，看白色侧锋、泡沫团和蜡笔圈是怎么让一张静止的纸充满水下动感的。
* **AI 辅助编程**：通用 AI 工具帮助我把视觉观察写成可以运行、可以测试的规则。但每一轮迭代要不要留下，仍然取决于它看起来是不是符合我们对水中运动的直觉。

更完整的设计过程与亲子反思仍在写作中。

## 🛠️ 本地运行

这个互动网页不需要构建，也没有运行时依赖。克隆仓库后，直接用现代浏览器打开 `index.html`：

```bash
git clone https://github.com/wfdiao/wax-and-water.git
cd wax-and-water
```

直接打开文件时，页面会使用项目里预先算好的物体轮廓。如果电脑上已经安装 Node.js，也可以启动一个本地服务器：

```bash
npx serve .
```
